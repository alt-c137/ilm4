# Мессенджер ilm4 — устройство, безопасность, план

Документ для программистов: как устроен мессенджер, где границы модуля, как
работает шифрование и что осталось сделать. Обновлять вместе с кодом.

## 1. Мессенджер — отдельный сервис внутри монолита

Сейчас мессенджер живёт в том же Django-проекте, что и сайт (так проще
запускать и менять), но написан как **отдельный модуль с одной входной дверью**,
чтобы потом вынести его в отдельный сервис без переписывания клиентов.

```
apps/chat/                  ← весь мессенджер (bounded context «messenger»)
  services.py               ← точка входа для остального кода: диалоги и сообщения
                              (open_direct, send_text, store_upload, upload_*, delete_message,
                              inbox, deliver_due, visible_messages …)
  rooms.py                  ← точка входа для групп и каналов (create, join, leave, роли,
                              каталог, прочитанность, уведомления) — см. §6
  models.py                 ← Thread, Message, ThreadKey (только мессенджер пишет в эти таблицы)
  keyring.py                ← ключи: главный ключ (KEK) → ключ чата (DEK) → сообщения и файлы
  filecrypt.py              ← шифрование файлов кусками (с перемоткой видео/аудио)
  shamir.py                 ← деление главного ключа на части (резервная копия)
  consumers.py              ← WebSocket: сообщения, «прочитано», сигналы звонков
  events.py                 ← формат сообщения для WebSocket/HTTP (один для сайта и приложения)
  media.py                  ← проверка и выдача вложений
  views.py                  ← страницы сайта
  management/commands/      ← chat_keys (ключи), chat_send_due (отложенные)
apps/api/views_chat.py      ← HTTP API для приложения (тонкий слой над services.py)
static/js/chat.js           ← клиент сайта
mobile/src/app/chat/        ← клиент приложения
```

**Правила, чтобы вынос в отдельный сервис остался простым:**

1. Другие разделы (никях, объявления, сделки) **не трогают модели чата напрямую** —
   только `apps.chat.services`. Сейчас это вызов функции, после выноса — HTTP/RPC-вызов
   с теми же аргументами.
2. Мессенджер знает о пользователе только `user_id` и имя/аватар (для выноса — через
   API аккаунтов или копию профиля).
3. Сайт и приложение говорят с мессенджером одним протоколом: HTTP API + WebSocket
   с JSON-событиями (`msg`, `read`, `signal`, `error`). Формат — `events.message_payload`.
4. Особые правила раздела (никях: запрет контактов, свидетель) — проверки в
   `services.py`, вызываются через «хуки», а не размазаны по view.

**Почему Django и нормально ли это.** Да. На Django написаны Instagram (сервер),
Pinterest на старте, Disqus. Живые соединения держит Channels (ASGI), очереди — Redis.
Когда нагрузка вырастет до сотен тысяч одновременных соединений, обычно выносят только
шлюз WebSocket на Go/Elixir/Rust — база, API и клиенты при этом не меняются.

## 2. Безопасность — как в Telegram

| | Telegram | ilm4 |
|---|---|---|
| Связь устройство ↔ сервер | MTProto 2.0 (свой протокол) | **TLS 1.3** (HTTPS/WSS), стандарт банков и Signal |
| Обычные чаты на сервере | зашифрованы, ключи отдельно от данных | **AES-256-GCM, свой ключ у каждого чата, ключи чатов зашифрованы главным ключом** |
| Файлы (фото, голос, кружки) | зашифрованы | **зашифрованы тем же ключом чата, кусками по 64 КБ** (перемотка работает) |
| История с нового устройства | да | да |
| Кто может прочитать обычный чат | Telegram | только сервер с главным ключом; модератор — **только по жалобе, с записью в журнал** |
| Звонки | сквозное шифрование, 4 эмодзи для сверки | **сквозное шифрование WebRTC (DTLS-SRTP), 4 эмодзи из отпечатков ключей** |
| Секретные чаты | E2E, одно устройство | **фаза S** (протокол Signal, только в приложении) |

### 2.1. Ключи («матрёшка», envelope encryption)

```
CHAT_MASTER_KEYS (KEK, .env / хранилище ключей; НЕ в базе)
   │ AES-256-GCM, AAD = "ilm4:dek:v1:thread:<id>"
   ▼
ThreadKey.wrapped (DEK — свой у каждого чата, 32 случайных байта; в базе — только зашифрованным)
   │ AES-256-GCM, AAD = "ilm4:msg:v1:thread:<id>"  /  "ilm4:file:v1:thread:<id>:chunk:<n>:last:<0|1>"
   ▼
Message.body (enc2:…)   и   файлы вложений (*.enc)
```

* AAD («привязка») не даёт переставить зашифрованный текст в другой чат.
* `CHAT_MASTER_KEYS=k2:<base64>,k1:<base64>` — первый ключ текущий, остальные — старые,
  только для чтения при смене ключа.
* Смена ключа: добавить новый первым → `manage.py chat_keys rotate` (перешифровывает
  только ключи чатов, секунды) → убрать старый.
* Резервная копия главного ключа: `manage.py chat_keys split` — 3 части, любые 2
  восстанавливают (схема Шамира, `shamir.py`). Части хранить **офлайн и у разных людей**,
  никогда не рядом с бэкапом базы.
* Старый формат `enc1:` (Fernet, один ключ на всё) читается; `chat_keys migrate`
  переводит всё на новый формат, включая файлы.

Фото анкет никяха и архив переноса никяха пока шифруются старым ключом `CHAT_ENCRYPTION_KEY`
(Fernet) — это отдельная подсистема (apps/nikah); перевести на ключи v2 — задача на будущее.

На ПК без `CHAT_MASTER_KEYS` используется ключ «dev», выведенный из `SECRET_KEY` (только разработка;
прод без `CHAT_MASTER_KEYS` не запускается — config/settings/prod.py).

### 2.2. Доступ модератора

В админке переписки нет. Жалоба из чата привязывается к диалогу; модератор
открывает **последние сообщения этого диалога** со страницы модерации, и каждое
открытие пишется в журнал (кто, когда, какой диалог, по какой жалобе).

### 2.3. Звонки

WebRTC шифрует голос и видео всегда (DTLS-SRTP), ключи создаются на устройствах.
Сервер передаёт только служебные сигналы. Чтобы сервер не мог незаметно встать
посередине (подменить ключи), оба собеседника видят **4 эмодзи**, вычисленные из
отпечатков DTLS-ключей обеих сторон: `SHA-256(min(fpA,fpB) | max(fpA,fpB))` →
4 байта → 4 эмодзи из общего списка (`static/js/call_emoji.js` и
`mobile/src/lib/callEmoji.ts` — списки обязаны совпадать, это проверяет тест).
TURN-сервер пересылает уже зашифрованный поток и прочитать его не может.

|---|---|---|

Отложенные сообщения отправляет `manage.py chat_send_due` (сервис `jobs` раз в минуту).

## 4. Чаты разделов: один мессенджер, разные типы чатов

У диалога есть контекст — `Thread.context_type` + `context_id` (`contexts.py`): ключ раздела из
`core/publications.py` (`buy`, `jobs`, `services`, `transport`, `doctors`…), `nikah` или `support`.

| Тип | Папка | Что особенного |
|---|---|---|
| обычный (`''`) | Личные | ничего |
| объявление, услуга, перевозка, поездка (попутчики) | Покупки / Услуги | **свой чат на каждое объявление**; карточка вверху (фото, цена, «снято с публикации»); подсказка о предоплате; предупреждение, если просят предоплату или карту (`contexts.SCAM`) |
| вакансия | Работа | карточка; кнопка «Отправить моё резюме»; подсказка «не платите за трудоустройство» |
| врач | Услуги | «переписка не заменяет приём» |
| никях | Никях | свидетель-махрам, запрет контактов, фото только защищённым обменом, без скриншотов |
| поддержка | Поддержка | чат с аккаунтом из «Настройки сайта → аккаунт поддержки» |

Контекст принимается, только если объект принадлежит собеседнику (`contexts.resolve`) — чат «по чужому
объявлению» открыть нельзя. Ссылка с сайта: `/chat/start/?user=<id>&ctx=buy&ctx_id=<id>`; приложение —
`POST /api/v1/pubs/<key>/<id>/message/`. Папки считает `services.folders_for`.

## 5. Фото, видео, файлы — как в Telegram

| Что | Как отправляется |
|---|---|
| Фото | пересохраняется без геометок, до 2048 px |
| Голосовое | моно, ~32 кбит/с (сайт: MediaRecorder, приложение: `VOICE_PRESET`) |
| Кружок | 480p, ~1 Мбит/с, до 60 с |
| Видео | после загрузки сервер пережимает в MP4 H.264 до «качества видео» из настроек (480/720/1080, по умолчанию 720p) — `transcode.py`, ffmpeg из пакета `imageio-ffmpeg`; исходник не хранится |
| **Файл** | «Отправить файлом»: любой файл **без сжатия**, до «файл не больше, МБ» (по умолчанию 2000 МБ ≈ 2 ГБ, как в Telegram); имя файла хранится зашифрованным; отдаётся только на скачивание. Программы и скрипты принимаются, но получатель видит предупреждение (`media.RISKY_EXT`) |

Видео на телефоне сжимается **до отправки**: iPhone — при выборе (720p), Android — модулем
`react-native-compressor` (`mobile/src/lib/upload.ts`; только в собранном приложении — в Expo Go модуля нет,
тогда сжимает сервер). Сервер в любом случае приводит видео к качеству из настроек. Сжатие на сервере идёт
по одному ролику за раз на весь сервер (`transcode._queue` + файл-замок) и не больше двух ядер.

Все вложения шифруются потоком (`filecrypt.seal_file`) — большой файл не читается в память целиком.

### 5.1. Большие файлы: загрузка частями

Один запрос больше ~100 МБ не пройдёт ни через nginx, ни через Cloudflare, а обрыв связи начинал бы
всё заново. Поэтому файл и видео крупнее 16 МБ идут частями по 4 МБ (`services.PART`) — так же устроен Telegram.

```
POST /chat/<чат>/upload/begin/      {kind, name, size, duration?, caption?, silent?, schedule?}
                                     → {upload: <id>, part: 4194304, received: 0}
POST /chat/upload/<id>/part/?offset=N   тело запроса — сырые байты части → {received}
                                     не по порядку → 409 {received: с какого места продолжать}
GET  /chat/upload/<id>/              → {received, size}   (после обрыва связи)
POST /chat/upload/<id>/finish/       → сообщение (как обычная отправка)
POST /chat/upload/<id>/cancel/
```
То же под `/api/v1/chat/…` для приложения. Каждая часть **сразу шифруется** ключом чата и дописывается
в файл (`filecrypt.begin/append`, модель `chat.Upload`) — открытого текста на диске нет ни секунды.
Брошенные загрузки удаляются через сутки (`chat_send_due` → `services.purge_uploads`).

Защита диска: предел размера файла, дневной лимит на человека («Настройки сайта»), не больше 5 загрузок
одновременно, запас свободного места (`CHAT_DISK_RESERVE_MB`).

## 6. Группы и каналы

Группа и канал — тот же `Thread` (`kind = group | channel`): шифрование, вложения, большие файлы,
отложенные сообщения работают так же, как в личном диалоге. Отличия — в `rooms.py`.

| | Личный диалог | Группа | Канал |
|---|---|---|---|
| Кто пишет | оба | все участники (или только админы — настройка) | владелец и админы |
| Участник | `Thread.participants` | + запись `Member` (роль, «без звука», `last_read_at`) | то же |
| Как попасть | написать человеку | ссылка-приглашение; публичная — из каталога | то же; адрес `/c/<имя>/` |
| Прочитанность | `Message.read_at`, ✓✓ | `Member.last_read_at`, без галочек | то же + счётчик просмотров поста |
| Уведомления | колокольчик + пуш | только пуш (кому не «без звука») | то же |
| Звонки | да | нет | нет |

* Роли: `owner` → `admin` → `member`; удалённый админом — `banned` (по ссылке не вернётся).
  Владелец ушёл — группа переходит старшему админу (или участнику), последний ушёл — удаляется.
* Добавить напрямую админ может только тех, с кем у него уже есть личный диалог (иначе это рассылка спама);
  остальным — ссылка-приглашение (`Thread.invite_code`, её можно перевыпустить).
* Публичные (`is_public`) видны в каталоге `/chat/channels/` и открываются на чтение любому вошедшему
  (`rooms.can_read`) — как предпросмотр в Telegram; писать и получать уведомления — после вступления.
* Создание: только с подтверждённым номером, не больше 5 в сутки на человека.
* Удалить сообщение у всех: своё — автор, любое — владелец и админы (`services.delete_message`, событие `del`).
* Выключатели в «Настройках сайта»: `chat_groups_enabled`, `chat_channels_enabled`,
  `chat_channels_staff_only` (каналы заводят только сотрудники), `chat_group_max_members`.
  Выключенный вид скрывается целиком: из списка чатов, каталога и по прямой ссылке.
* Модерация: жалоба на группу / канал попадает в общую очередь; сотрудник с правом `chat.change_thread`
  может закрыть (`closed`) или отметить «официальный» (`platform_verified`) — со страницы сведений
  или в админке («Группы и каналы»). Личных диалогов в админке по-прежнему нет.

Нет пока: ответы и реакции, закреплённые сообщения, упоминания, опросы, комментарии к постам канала,
групповые звонки (нужен отдельный медиасервер).

## 6.1. Люди: @имя, поиск, профиль, приватность

Код — `apps/accounts/people.py` (одно место для правил: что показать конкретному зрителю).

| Что | Как устроено |
|---|---|
| Имя пользователя | `User.handle`, 4–32 знака, латиница/цифры/`_`, первая — буква. Одно пространство имён с группами и каналами. Имена из `people.RESERVED` (ilm4, support, admin…) — только сотрудникам |
| Поиск | `people.search`: по началу @имени либо по номеру целиком (`phone_key`, только подтверждённые номера и `findable_by_phone`). Номер в ответе не отдаётся. 30 поисков по номеру в час |
| Новый диалог | `services.open_direct`; не больше 30 новых диалогов с незнакомыми в сутки (`people.check_new_chat`) |
| «В сети» | `User.last_seen_at`; отметка — `people.touch` (API-декоратор, `LastSeenMiddleware`, пинг раз в минуту из приложения и открытой вкладки). «В сети» — моложе 2 минут |
| Приватность | `phone_privacy`, `seen_privacy`: все / близкие друзья / никто; `findable_by_phone`. Время в сети — взаимно: скрыл своё — не видишь чужое |
| Соцсети | `SocialLink(kind, value, privacy)`; ссылки строятся только на известные домены, произвольный `javascript:` невозможен |
| Близкие друзья | `CloseFriend(owner, friend)` |
| «Без звука» в личном чате | строка `Member(muted=True)` для диалога; уведомление собеседнику приходит тихим |

Страницы сайта: `/chat/people/`, `/accounts/u/<id>/`, `/accounts/profile/`. API: `/people/`, `/users/<id>/`,
`/users/<id>/chat/`, `/users/<id>/close/`, `/me/links/`, `/me/close/`, `/chat/<id>/mute/`, `/chat/<id>/media/`, `/ping/`.
Приложение: `chat/people.tsx`, `user/[id].tsx`, `privacy.tsx`, `profile-edit.tsx`, общие части — `ui/profile.tsx`.

## 7. План и статус

- [x] **A.** Границы модуля: `services.py`, остальные разделы — только через него.
- [x] **B.** Шифрование v2: ключ на чат, AES-256-GCM, файлы, смена ключа, перевод старых данных.
- [x] **C.** Резервная копия главного ключа: 3 части, любые 2 (Шамир).
- [x] **D.** Доступ модератора к переписке только по жалобе + журнал.
- [x] **E.** Звонки: 4 эмодзи для сверки ключей (сайт + приложение).
- [x] **F.** Отправка без звука, запланированные сообщения.
- [x] **G.** Одна кнопка голос/кружок с удержанием, «замком» и отменой; анимации.
- [x] **I.** Свой чат на объявление, папки, карточка, подсказки и предупреждения по типу чата, чат поддержки.
- [x] **J.** «Отправить файлом», сжатие видео на сервере, лёгкие голосовые.
- [x] **L.** Файлы до 2 ГБ частями с продолжением после обрыва; любые типы файлов с предупреждением;
  сжатие видео на Android до отправки (проверить в собранном приложении — `ЧТО_ДОДЕЛАТЬ.md`).
- [x] **M.** Группы и каналы: роли, приглашения, публичные адреса, каталог, «без звука», просмотры постов,
  удаление сообщений, выключатели и модерация (§6).
- [ ] **N.** Ответы и реакции, закреп, упоминания, комментарии к постам канала, опросы.
- [ ] **H.** Привязка сертификата в приложении (certificate pinning). Делать **перед
  выпуском в магазины**, когда известен боевой сертификат: пиновать открытый ключ
  промежуточного центра сертификации + запасной ключ, иначе плановая смена сертификата
  у Cloudflare «отключит» все установленные приложения. Нужна нативная сборка (не Expo Go).
- [ ] **S.** Секретные чаты: протокол Signal (X3DH/PQXDH + Double Ratchet) из готовой
  проверенной библиотеки, только в приложении, одно устройство, отпечаток ключа, таймер.
  Сервер хранит только открытые ключи устройств и пересылает зашифрованные пакеты.
- [ ] **K.** Главный ключ — в хранилище ключей (KMS/Vault) вместо `.env`, когда появится
  инфраструктура.
