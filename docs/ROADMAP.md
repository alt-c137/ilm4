# ilm4 — архитектура роста (v34)

Как добавлять крупные вещи так, чтобы «завтра ничего не упало».

## 0. Принципы

1. **Каждая крупная функция — за выключателем.** Раздел — `ModuleConfig`
   (вкл / выкл / скоро), поведение — флаг в `SiteSettings`. Включили →
   проверили на живых людях → откатили одной галочкой, без деплоя.
2. **Сначала модель данных, потом интерфейс.** Поля «на будущее» добавляются
   заранее, с безопасными значениями по умолчанию (как `Message.kind` и
   `attachment`). Потом включаем функцию без миграций на горячей базе.
3. **Деньги чужих людей держит лицензированный партнёр, а не мы** (раздел 5).
4. **Всё, что пишут люди, модерируется.** Жалоба, скрытие, журнал действий
   (`AuditLog`).
5. **Одна механика — много мест.** Отзывы: одна модель на продавцов,
   заведения и врачей. Договор автора: один декоратор `pledge_required`
   на все формы публикации.

## 2. Мессенджер «как Telegram»

**Готово (v34), каждая функция выключается в админке → Настройки сайта:**

| Функция | Как устроено | Выключатель |
|---|---|---|
| Личные чаты, «прочитано» ✓✓, контекст сделки | WebSocket (Channels + Redis) | раздел `chat` |
| Шифрование переписки в базе | Fernet (AES + HMAC), ключ `CHAT_ENCRYPTION_KEY` | всегда вкл. |
| Фото | Pillow: пересохранение без EXIF/геометок, ≤2048px, ≤10 МБ | `chat_photos_enabled` |
| Голосовые (до 5 мин) | запись в браузере (MediaRecorder), mp4/webm/ogg | `chat_voice_enabled` |
| Видеокружки (до 60 с) | запись с фронтальной камеры, mp4/webm | `chat_circles_enabled` |
| Аудио- и видеозвонки 1:1 | WebRTC: голос и видео идут напрямую между людьми, сервер только передаёт сигналы | `chat_calls_enabled`, `chat_video_calls_enabled` |
| Входящий звонок на любой странице | личный канал `/ws/me/` | вместе со звонками |
| Записи о звонках в переписке | «Видеозвонок · 3:12», «Пропущенный» | — |
| Найти знакомых из контактов | браузер шлёт только SHA-256 номеров; искать можно лишь тех, кто разрешил; 10 проверок/час | галочка в профиле |

Вложения выдаются **только участникам диалога** (в проде — через nginx
`X-Accel-Redirect`, прямой доступ к `/media/chat/` закрыт).

**Для звонков в проде нужен TURN-сервер** (coturn, ~5 € в месяц + трафик):
без него ~10–20 % звонков через мобильные сети не соединятся. Адрес и
логин вписываются в админке, код менять не нужно.

**Дальше:**

| Фаза | Что | Что нужно |
|---|---|---|
| M3 | Группы и каналы | поля уже в базе (`Thread.kind/title/owner`); роли, приглашения, рассылка подписчикам |
| M4 | Пуш-уведомления на телефон | Web Push (VAPID) сейчас; FCM/APNs — в нативных приложениях |
| M5 | Групповые звонки | SFU: LiveKit / mediasoup — отдельный сервер |
| M6 | Нативные приложения iOS/Android | сейчас PWA (ставится на экран); нативные — для фоновых звонков и контактов на iPhone |

### Защищённая переписка: что есть и что можно

- **Сейчас:**
  - канал зашифрован HTTPS/WSS — никто между человеком и сервером не прочитает;
  - в базе текст зашифрован — утечка базы или бэкапа не раскрывает переписку;
  - вложения видят только участники.
- **Обычные чаты Telegram устроены так же:** шифрование «клиент — сервер».
  Сквозное шифрование (E2E) в Telegram — только в «секретных чатах».
- **«Секретные чаты» (E2E) у нас** — отдельная фаза. Ключи только на
  устройствах, WebCrypto: ECDH P-256 + AES-GCM, позже протокол Signal.
  Честные ограничения:
  - переписка живёт только на устройстве; потерял телефон — потерял историю;
  - нельзя пожаловаться с доказательством (модератор не видит текст);
  - сложно с несколькими устройствами.

  Поэтому E2E — опцией, как в Telegram, а не по умолчанию.
- **Ключ шифрования базы (`CHAT_ENCRYPTION_KEY`)** — хранить в `.env` и
  **резервной копией отдельно**. Без ключа старые сообщения не прочитать.
  Поиск по тексту сообщений на сервере невозможен — это цена шифрования.

## 3. Каналы и блоги (как Дзен) и лента

**Каналы/блоги** — отдельное приложение `apps/blogs`:
`Channel` (владелец, slug, аватар, `platform_verified`), `Post` (заголовок,
текст, обложка, статус модерации, дата публикации), `Subscription`,
реакции, комментарии. Лента: подписки → свежее → популярное.

**Лента как TikTok/Reels** — после блогов. Сложность не в интерфейсе, а в
инфраструктуре: перекодирование видео в HLS, CDN, модерация видео
(контент-политика), рекомендации. MVP без видео: вертикальная лента
карточек (посты блогов, объявления, новости) с тем же жестом пролистывания.

## 4. Доверие: отзывы, проверка, репутация

- Готово: одна оценка от человека на объект; себя оценить нельзя;
  скрытые не считаются; владелец отвечает.
- Дальше:
  - **отзывы «после сделки»** — только если был диалог или заказ
    (защита от накруток);
  - жалоба на отзыв;
  - минимальный возраст аккаунта.
- «Проверено ilm4» = проверены документы и контакты. Рядом **всегда**
  пояснение: это не гарантия качества, а отсутствие проверки — не повод
  не доверять.

## 5. Деньги: кошелёк, фриланс, P2P и лицензии

> Не юридическая консультация. Перед запуском платежей — юрист в каждой
> стране, где принимаете деньги.

**Сейчас (обычно без лицензии):**
- Баланс — **предоплата за услуги самой платформы**: поднятие объявления,
  анкеты, публикация.
- Нельзя вывести, нельзя перевести другому человеку.
- Деньги принимает **лицензированный платёжный провайдер** (Payme / Click /
  Uzum — Узбекистан, Stripe — международно, Tribute — пожертвования). Он же
  хранит данные карт (PCI DSS), мы их не видим.
- Нужны: публичная оферта, правила возврата, учёт и налоги.

**Требует лицензии:**
- вывод денег пользователям;
- переводы между людьми;
- **хранение денег одного человека для другого (эскроу, «безопасная
  сделка», P2P)**.

Это деятельность платёжной организации:
- Узбекистан — лицензия ЦБ;
- Россия — 161-ФЗ;
- ЕС — PSD2 (PI или EMI).

**Как делать фриланс с удержанием денег без своей лицензии:** через
маркетплейс-продукт провайдера (Stripe Connect; в Узбекистане — сплитование
или аккредитив через банк-партнёр). Деньги держит лицензированная сторона,
мы задаём правила и получаем комиссию.

**Безопасная сделка — реализована (`apps/deals`), по умолчанию выключена:**

```
предложен → принят исполнителем → оплачен (деньги удержаны) → сдан
          → принят заказчиком → выплачено исполнителю (минус комиссия)
          ↘ спор → решение модератора в админке (возврат / выплата)
предложен / принят → отменён (деньги ещё не списаны)
```

- Комиссия и срок автопринятия — в настройках (по умолчанию 5 % и 3 дня);
  автопринятие — командой `release_due_deals` по расписанию.
- Все движения денег — через журнал кошелька: `ESCROW_HOLD / RELEASE /
  REFUND`. Двойная выплата невозможна, есть тесты.
- Входы: кнопка со щитом в чате, «Заказать с гарантией» на странице
  исполнителя, меню профиля → «Сделки».
- **Купля-продажа сюда не входит** — как вы и хотели.
- **Пополнение (`apps/payments`):** интерфейс провайдера — один класс на
  способ оплаты. Способ появляется на странице пополнения, когда в `.env`
  заданы ключи. Зачисление — только после подтверждения оплаты, повтор не
  зачисляет дважды.
- **Криптовалюта:** в Узбекистане и России приём крипты от резидентов
  ограничен законом. Подключать только через лицензированный шлюз и после
  консультации юриста.

**По шариату:**
- никаких процентов на остатки (риба);
- комиссия платформы — плата за услугу (уджра), раскрыта заранее;
- условия, сроки и результат заказа — ясно прописаны (без гарара).

## 6. Серверы и деньги на инфраструктуру

> Цены ориентировочные (2025–2026), проверяйте на сайтах провайдеров.

**Где арендовать:**
- **Hetzner** (Германия/Финляндия) — лучшее соотношение цены и качества,
  до Ташкента ~70–90 мс;
- **DigitalOcean / Vultr** (Франкфурт, Амстердам) — дороже, удобнее;
- **Cloudflare** перед сайтом — бесплатно: CDN, защита от DDoS, HTTPS;
- **для данных граждан Узбекистана** — локальный хостинг в Узбекистане
  (см. закон ниже).

| Этап | Нагрузка | Что стоит | ≈ в месяц |
|---|---|---|---|
| **Старт** | до ~5–10 тыс. человек в день | 1 VPS 4 vCPU / 8 ГБ (всё в Docker) + бэкапы + хранилище файлов (Cloudflare R2 или S3) + TURN на том же сервере | **$30–60** |
| **Рост** | десятки тысяч в день, голосовые и кружки | 2–3 сервера приложения, управляемый Postgres, Redis, отдельный воркер ffmpeg, отдельный TURN | **$200–500** |
| **Как Instagram/YouTube** | сотни тысяч и миллионы, видео-лента | видео-конвейер (Cloudflare Stream / Bunny Stream: хранение и раздача по минутам/ГБ), SFU для групповых звонков, модерация с ИИ, команда | **от $1–5 тыс.** и растёт с трафиком |

Главная статья расходов у видеосервисов — **трафик видео**, а не серверы.
Поэтому видео — через специализированный сервис с оплатой по факту, а не
на своих серверах.

**Профессионально ли это?** Да: Django + Postgres + Redis + WebSocket +
S3 + CDN — это стек, на котором начинали крупные продукты. Instagram
изначально написан на Django. Масштабирование идёт по шагам из таблицы:
выносим файлы в S3/CDN, базу — в управляемый Postgres, видео и звонки — в
специализированные сервисы. Переписывать с нуля не нужно.

**Законы о хранении данных** (уточнить у юриста):
- Узбекистан: персональные данные граждан — на серверах внутри страны
  (закон «О персональных данных», ст. 27-1);
- Россия: 152-ФЗ, локализация данных граждан РФ;
- ЕС: GDPR — не локализация, но строгие правила согласия и удаления.

## 7. Перед каждым выкатом — чек-лист

- `python manage.py migrate` (миграции только добавляют поля с
  безопасными значениями по умолчанию).
- `collectstatic` — имена статики с хешем, кэш браузера не мешает.
- Redis для Channels в проде (`REDIS_URL`), иначе чат только в одном
  процессе.
- Сервер приложения — **daphne (ASGI)**: `entrypoint.sh`. Nginx проксирует
  `/ws/` с `Upgrade`. На gunicorn (WSGI) WebSocket не работают.
- `CHAT_ENCRYPTION_KEY` задан, его копия — вне сервера.
- Раз в час: `python manage.py release_due_deals` (автопринятие сделок).
- Резервная копия базы до миграции.
- `.env`:
  - `SECRET_KEY`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`;
  - `GOOGLE_OAUTH_CLIENT_ID/SECRET` + redirect URI
    `https://<домен>/accounts/google/callback/`.
- Мониторинг ошибок (Sentry) и ограничение частоты для отзывов и чата
  (следующий шаг).
